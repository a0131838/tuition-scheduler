# TASK-20260813 AI OS 统一原系统员工登录

状态：`READY FOR GUARDED DEPLOY`

线上代理复验：Nginx 的 `x-forwarded-host` / `host` 优先于历史内部 `NEXT_PUBLIC_APP_URL`，避免登录页跳到 `localhost:3000`。

## 目标

SGT AI OS 网页端不再维护或要求第二套员工用户名和密码。员工只使用正式 Tuition Scheduler 的邮箱、密码和账号状态；已登录正式系统时进入 AI OS 无需再次输入，未登录时先到正式登录页并在成功后返回原 AI 页面。

## 安全设计

- 正式系统是唯一身份来源；AI OS 不读取、复制或保存正式密码和密码摘要。
- 正式系统读取现有 `ts_admin_session`，签发60秒、HMAC签名、限定`sgt-ai-os`受众的短时身份凭证。
- AI OS 校验后立即换成8小时`HttpOnly + Secure + SameSite=Lax`会话；短时凭证不保留在页面URL。
- `next`仅接受本站相对路径，禁止开放重定向。
- 停用账号、修改正式密码和调整角色仍只在正式系统操作；新登录会按正式账号重新签发权限。
- 老板、经理、财务、教务、客服与只读权限由正式账号服务端映射，员工不能在浏览器选择或提升角色。

## 员工操作影响

- 岗位：所有使用AI网页的内部员工。
- 修改前：先登录正式系统，再输入AI OS独立用户名和密码；浏览器可能显示系统密码弹窗。
- 修改后：只使用正式系统邮箱和密码；点击AI OS后自动进入，未登录则登录一次后返回。
- 减少的输入/页面/决定：删除第二套账号、第二次密码输入和Mac钥匙串分发步骤。
- 正式系统影响：只新增只读当前会话与签发短时身份的GET入口，不修改排课、课包、工资、财务或工单数据。

## 界面复杂度核对

- 一级入口：不增加。
- 当前状态主要动作：未登录时只有原系统“登录”。
- 普通流程人工决定：0。
- 重复询问：不再重复询问密码。
- 技术术语：员工页面不显示令牌、签名或角色映射。

## 验证

- 正式侧测试覆盖：现有会话复用、短时凭证、角色白名单、相对返回路径和密码不外传。
- AI侧测试覆盖：签名会话、防篡改/过期、未登录跳转、短时凭证换取安全Cookie、URL清理和原小程序签名身份不回退。
