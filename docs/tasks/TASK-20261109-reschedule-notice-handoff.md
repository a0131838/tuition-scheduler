# Reschedule notice and handoff

Parents may keep an old screenshot even after a lesson changes. Existing correction tasks depend on the prior reminder; the same-day change needs an immediate, owned task and a separate confirmation by the pickup contact.

Validated time changes from web, Mini Program and batch/operations paths create a notice inside the same transaction, with old/new Singapore date/time, current location, and family recipient. One notice per changed lesson and linked household/group; missing group data is filled by staff before marking sent. A newer change supersedes its prior notices, including confirmed ones. The current schedule and task are locked in a consistent order before any action. Existing exact single-lesson reminder corrections are not duplicated when their recipient and content are covered; mixed legacy corrections remain independently reviewable.

Eva and Emily are the designated duty pair, resolved from their existing unique non-observer Admin/CS identities; no permissions are granted. The actual designated editor owns the notice (otherwise assigned to Eva if available). Only the pair can operate the new notice; only its current owner can record sending/confirmation. Explicit handoff keeps the deadline; after ten minutes, one backup takeover is available. Sending requires the original group name and screenshot and moves to WAITING_PARENT; recording the contact and channel completes it. Already-started classes show exception follow-up rather than a stale copy button. No automated WeChat group send, financial write, role change or schema migration.

The employee Mini Program foreground checks its own notice summary every 30 seconds and shows a deduplicated alert for new/overdue/takeover/urgent work. It stops polling when hidden or in the parent portal. The 5/10-minute timers are calculated from server timestamps; there is no closed-app delivery. Production config has no dedicated staff subscription template; keep the agreed human handoff for urgent work until that is available.

Verification: isolated PostgreSQL transaction/recipient/role/handoff/supersession/rollback checks, targeted communications regressions, existing backend suite, production build, staff API authentication and screenshot/send workflow, Eva-to-Emily web handoff and 390px confirmation workflow, native JS syntax and release audit. Native upload is separate; do not claim it is published from server deployment.
