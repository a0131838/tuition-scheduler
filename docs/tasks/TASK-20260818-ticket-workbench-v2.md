# TASK-20260818：网页工单 V2 单一步骤工作台

## 目标

让 Eva 在网页端处理工单时与员工小程序采用同一套工作思路：先看到当前能做的工作，打开一张工单后只做一个当前决定，不再从大表格、流程状态和重复表单中寻找入口。

## 问题

- 原网页工单首页同时显示工作地图、超时队列、录入链接、筛选器和宽表格，日常处理入口不突出。
- “实际已经处理”“无需执行”和“部分已处理”虽然已有安全后端能力，但藏在正式执行动作下方，Eva 很难找到。
- 详情页把家长需求、内部流程、正式动作、状态和编辑字段平铺，和小程序的动作优先结构不一致。
- 旧工单在没有历史课程时容易让员工误以为必须补造一条课程记录才能完成。

## 实现

1. 增加统一的 `ticket-operation-card` 视图模型，把工单归为“现在处理 / 等待家长或老师 / 已结束”，并只给出一个当前动作。
2. 网页工单首页默认显示紧凑待办队列，按当前动作、截止时间和负责人排序；点击直接进入详情的当前决定。
3. 工作地图、超时队列、录入链接、完整筛选器和旧宽表格收进“管理、录入链接与完整字段（高级）”。
4. 详情页顺序固定为：家长需求 → 当前决定 → 按需展开正式执行 → 完整资料与历史。
5. 对排课类工单明确区分两个入口：
   - 继续由正式系统执行排课、改课、取消或换老师；
   - 已在别处处理、确实无需处理、或部分已处理，只核验一次并自动更新工单。
6. 事后补录仍强制一次性核验说明和确认框，并沿用现有审计动作；不创建虚假课程，不直接修改课包、考勤、工资或财务。

## 权限与数据边界

- 没有新增数据库迁移。
- 没有改变原工单状态机、正式课表执行、冲突检查、权限和幂等规则。
- 没有修改正式课程、课包、课时、考勤、工资、财务或通知数据。
- 高级维护能力仍保留，但不再干扰日常处理。
