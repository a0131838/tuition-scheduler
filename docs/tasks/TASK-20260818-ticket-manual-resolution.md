# TASK-20260818 — 工单事后补录一次确认

## 目标

解决教务已经在正式课表或其他页面完成处理、但工单稍后才创建时，必须为每个动作重复选择“无需执行”、重复填写状态和说明的问题。

## 业务规则

- 正常排课、改课、取消和换老师仍进入正式课表执行，并继续使用原有权限、冲突和重复操作校验。
- 事后补录明确区分三种真实结果：
  1. 已在正式系统或其他页面处理完成；
  2. 整张工单确实无需处理（家长撤回、重复工单或需求失效）；
  3. 部分动作已经处理完成。
- 共同核验说明、操作者和核验时间整张工单只记录一次。
- “已处理完成”把对应动作记为已执行；“无需处理”把对应动作记为取消，不再使用同一个模糊状态表达两种含义。
- 全部动作已完成时，工单自动完成；整单无需处理时，工单自动取消；部分完成时，只保留未处理动作继续跟进。
- 已有真实执行动作的工单不能整单标记为“无需处理”，避免把已经发生的课程操作误写成无效需求。
- 没有结构化动作的历史工单允许直接做整单核验，因此不要求虚构历史课次。
- 每次整单核验写入可见处理记录和 `ADMIN_RESOLVE_TICKET_SCHEDULING_ACTIONS` 审计日志。

## 页面调整

- 排课执行单顶部新增“已经在别处处理过？整张工单只填一次”。
- 逐项资料和状态表单降级到“单项例外”，默认折叠。
- 原“无需执行”改名为“单项无需处理”，避免员工把“已经处理完成”误选成“无需执行”。
- 历史、状态与高级修改继续保留给异常修复，不作为日常流程。

## 安全边界

- 不修改正式课表、课包、扣课时、老师工资或通知规则。
- 不绕过正常排课执行的冲突检查。
- 不新增数据库迁移，不改写历史业务数据。
- 本次只调整正式网页端工单的人工补录关闭流程；员工小程序的正常 AI 工单执行路径保持不变。

## 验收场景

1. Eva 先在学生课表完成改课、后收到工单：选择“已处理完成”，写一次说明并确认，所有未完成动作锁定，工单自动完成。
2. 家长撤回或重复提交：选择“整张工单确实无需处理”，写一次原因，工单自动取消。
3. 多动作工单只完成其中一部分：选择“部分动作已经处理完成”，勾选已完成项；其余动作继续留在待办。
4. 旧工单没有历史课程或结构化动作：允许按实际结果直接完成或取消，不要求选择不存在的原课次。
5. 工单已有动作实际执行：系统拒绝整单“无需处理”，防止审计语义被改错。
