# TASK-20260812 AI 工单合并与并发保护

## 目标

同一学生反复提交同一事项时，保留每张原始工单，但只生成一个教务处理任务；正式执行前再次核对全部工单版本，并防止另一张工单同时修改同一课次。

## 本次实现

- AI 执行包携带主工单、重复提交和补充提交的版本快照；冲突工单不进入执行包。
- 正式接口逐张核对学生、状态和更新时间；任一变化都要求重新读取。
- 同一课次、学生或工单组使用短时执行锁，避免员工重复点击或两张工单并发写入。
- 排课、改课、取消、换老师、地点调整和业务处理均能一次更新合并成员；家长只收到主工单的一次完成通知。
- 家长请求列表把仍在处理的同类提交合并为一条状态，原始记录不删除。
- 员工小程序显示“已合并几次提交”或“要求冲突”，不再要求教务逐张猜测。

## 安全边界

- 不修改现有课时、工资、出勤、共享课包和通知规则本身。
- 所有正式写入仍需员工预检并确认；冲突、版本变化或并发请求均阻断。
- 验证不得使用或修改生产业务数据。

## 验证结果

- 47 项正式工单/小程序聚焦回归、TypeScript 和 247 页面生产构建通过。
- Docker PostgreSQL 隔离 UAT 通过：整月新排课、整批改课、扣/不扣课取消、月卡、团课、换老师、五类业务流程、正式 HTTP 预检/执行、越权、过期和重复点击，共 24 条审计记录。
- 隔离 UAT 首轮发现历史测试工单会被并发门禁误拦截，已收紧为只拦截当前主工单之后创建的竞争工单；复验通过。
