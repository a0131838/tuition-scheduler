# 工单结果核验整改：第一批

日期：2026-09-09。基线：r403 / 976978a1a151b08eb868729baafb7c626482ed9b。

## 用户要求与边界

依据四份教务工单反馈执行整改，不增加导航入口，不强制先用AI。小程序已经正式发布，本轮客户端必须先上传开发版、指定体验版及验收，不直接发布。生产历史数据只读，不恢复/取消测试真实课程，不自动重开或关闭历史工单。

## 本批改动

1. 原课程与已有结果统一为同一学生、按起始日期31天窗口查询，50条分页；可定位过去、未来及已取消课程，不再只显示未来30条。
2. 新增 `TicketSchedulingAction.resultSessionIds`，保留旧 `resultSessionId` 兼容。已有结果关联在事务内锁工单并校验真实状态，只更新工单和审计，不修改课程或考勤。
3. 取消核验必须看到原课实际 EXCUSED，扣课决策须一致；改课、换老师必须核对原课及目标。日期、科目、老师、时长不同须有确认变更的说明，不能凭任意同学生课程结束工单。
4. 明确节数按动作原说明识别并累计结果，未齐时保持待办。取消后仍需补课、仅写总课时未明确本次数量时保留协调待办，不自动视为全部完成。
5. 工单发起的日历取消传递准确动作上下文；历史原课程在同一学生页呈现。小程序返回工单时刷新，取消预览明确选中原工单。
6. AI展示为可选折叠区；正式执行网关再次核对已确认动作与课次范围，多周扩展越界即阻断。关联工单组须先验证成员和版本，再检查范围。

## 教务操作

入口不变：工单中心 → 原工单 → 课程处理与结果核验。

- 尚未处理：选择正确原课程后，进入原课表操作。通过工单入口完成后返回核对剩余动作。
- 已在别处取消：直接核验原课程，不恢复后再取消；未真实取消会被拒绝。
- 已在别处排课：按日期查找并选择实际课程，多节可分次关联；已有结果会保留，只补剩下的课。
- 有差异：先确认真实约定。确认变更后勾选对应项并填写确认人和依据，不随意关联凑完成。
- 尚有补课：保留待办，补充明确的补课动作及结果；家长撤回应记录无需执行，不冒充已排。
- 重复点击或看到已结束提示：刷新原工单，不重新排课、不删除课程。
