## 小程序职能学习路径

1. 全员工：主管发一次性码、员工本人登录绑定、身份核对、账号切换和安全退出。
2. 教务／客服：统一待办、工单、排课、学生 360、家长沟通和纠正。
3. 老师：课表、课程确认、点名、反馈、通知、报告、工资和调课。
4. 管理：异常监督、审批、沟通审计、提醒失败、账号和交接。
5. 教务／家长：教务生成一次性邀请、家长选择关系并绑定、教务复核 ACTIVE 状态和可见权限。
6. 销售：小程序资源查重和跟进；正式成交、合同、收款与建档回网页版交接。
7. 财务：员工端登录绑定；当前无独立财务小程序工作台，所有财务操作回网页版。
8. 全托管：小程序查看通用学生和请求；项目、任务、风险与报告回网页版全托管工作台。
9. 家长／学生端支持：邀请归属、过期或已使用、绑定失败、ACTIVE 状态、权限和工单排障。

## HR 质量门槛

- 每个模块显示基础、岗位核心或专项进阶阶段，并给出预计学习时间。
- 每个模块有三项中英双语学习目标和五道岗位情境题，不再共用同一套题。
- 实操必须在确认阅读并达到 80 分后开放。
- 实操证据拆分为培训数据、已核对最终结果和逐项自查，不能只写“已完成”。
- 主管必须按四项能力标准逐项确认；退回必须写具体返工要求，主管不得自我验收。

## 使用规则

1. 员工只使用《SOP 版本总表》中标记为“现行”的文件。
2. 标记为“待复核”的文件，主管可用于解释业务背景，但不可作为新员工独立操作依据。
3. 标记为“已替代”的文件只供审计和历史追溯，不再发给员工。
4. 合同样板、流程图和管理报告属于参考资料，不等于岗位操作 SOP。
5. SOP 文件名中的日期不是唯一判断依据；必须同时核对“状态”和“替代版本”。
6. 系统页面、权限、按钮、状态机或业务规则发生变化后，相关 SOP 立即进入“待复核”，复核通过后才恢复为“现行”。

## 培训完成标准

员工完成一项培训，需要同时满足：

1. 阅读当前版本 SOP。
2. 完成知识检查。
3. 使用培训账号或培训数据完成一次实操。
4. 主管按照结果检查表验收。
5. 记录完成日期、SOP 版本和验收人。

仅打开或阅读 PDF 不代表培训完成。

## 系统内培训

部署后员工从后台或老师端菜单进入 `/training`：

1. 打开岗位现行 SOP，或进入 `/training/library` 集中查看和下载本人岗位 PDF。
2. 确认已阅读当前版本。
3. 完成五题知识检查，80 分及格。
4. 使用培训数据完成实操并提交证据。
5. 管理者在 `/training/manage` 查看全部员工的未开始、进行中、待验收和已完成状态；符合验收条件的实操可通过或退回重做。

主管验收台默认显示全部非学生账号，不要求员工先产生培训记录。页面加载只汇总现有账号、培训岗位和当前版本进度，不会自动创建进度或把员工标记为完成。

主管可在 `/training/coverage` 查看 144 个网页页面与 54 个微信小程序页面（共 198 个）到 16 条主操作流程的完整映射。

员工的系统主角色继续控制实际系统权限；管理者可以在“系统使用者管理 → 培训岗位”中增加兼职培训岗位。附加培训岗位只增加课程，不增加财务、管理、教务或老师页面权限。

ADMIN 在培训中心采用全资料库监督模式，可以查看、下载和验收全部 35 份岗位教材，包括标记为仅老师学习的课程；教务／客服主角色可学习 20 个模块。这些设置只改变培训资料可见性，不绕过任何老师端、财务端、教务端或小程序业务权限。

岗位主流程、全部页面入口映射、旧版隔离和系统验收闭环已经完成。后续只按真实培训反馈调整题库、验收人和复训周期。
