# SGT 员工培训体系 HR 审计与改进

审计日期：2026-07-29  
审计范围：岗位学习路径、双语 PDF、知识检查、实操证据、主管验收、小程序职能覆盖和访问权限

## 审计结论

原体系已经具备登录控制、岗位分配、PDF、测验、实操和主管验收的完整技术闭环，但在人才培养质量上仍偏向“资料库”，没有充分证明员工能够独立完成工作。

主要问题：

1. 23 个模块共用同一套五题安全题，岗位区分度不足。
2. 实操证据只要求十个字符，无法证明对象、动作和最终状态。
3. 主管没有统一能力量表，验收标准可能因人而异。
4. 学习材料没有明确基础、岗位核心和专项进阶顺序。
5. 销售、财务、全托管、通用登录和家长学生端支持缺少独立小程序路径。
6. 员工在未完成阅读或测验时仍能看到实操提交界面，学习门槛不清楚。
7. 主管能够验收自己的模块，不符合培训职责分离原则。

## 本次改进

### 学习设计

- 模块总数从 23 增至 28。
- 小程序形成八条职能学习路径。
- 每个模块分为基础必修、岗位核心或专项进阶。
- 每个模块显示预计学习时间、三项学习目标和实操结果要求。
- 培训中心按阶段排序，先基础、再核心、最后专项。

### 知识检查

- 每个模块生成独立岗位题面。
- 五题分别检查：岗位实操结果、开始前核对、完整证据、异常停止和真正完成标准。
- 继续维持 80 分及格，但不再以通用安全题代替岗位能力题。

### 实操证据

- 只有确认阅读且测验通过后才开放。
- 必须分别填写培训数据名称或编号、重新核对后的最终状态和逐项自查。
- 服务端再次检查阅读和测验门槛，不能绕过页面直接提交。

### 主管验收

- 每个模块统一使用四项能力标准：
  1. 本人账号、正确岗位和正确培训数据；
  2. 按 SOP 顺序完成且没有绕过权限或业务门禁；
  3. 最终状态正确并有可核对证据；
  4. 能独立说明常见错误、停止条件和升级对象。
- 主管必须勾选已核对全部标准。
- 退回重做必须给出具体返工要求。
- 只允许验收当前培训版本和已满足阅读、测验、实操条件的提交。
- 禁止主管自我验收。

## 后续 HR 建议

1. 新员工入职时由直属主管确定完成期限，建议基础模块三天、岗位核心七天、专项模块三十天。
2. 每个岗位指定一名主验收人和一名备用验收人，避免同一主管长期成为瓶颈。
3. 上线两周后分析每题错误率、退回原因和平均完成时间，再调整题目与教材。
4. 对财务、课包、合同、家长发布和高风险全托管流程，每十二个月复训一次；系统发生重大变更时立即复训。
5. 新员工首次通过后安排一次真实工作影子观察，培训通过不等于可以无监督处理所有高风险业务。

## 完成定义

培训完成必须同时满足：阅读当前版、岗位题达到 80 分、结构化培训数据实操、主管按四项能力标准验收。下载 PDF、参加口头讲解或写一句“已完成”都不算完成。
