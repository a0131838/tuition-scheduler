# SGT SOP 维护与发布规则

版本：1.0
生效日期：2026-07-28

## 1. 状态定义

- `现行`：已经对照当前系统页面、权限和业务规则验证，可用于员工培训。
- `待复核`：业务内容可能仍然有效，但系统页面、入口、权限或上下游流程已经变化。
- `已替代`：存在明确的新版本，不再用于培训。
- `参考资料`：合同样板、流程图、指导报告或管理材料，不属于逐步操作 SOP。
- `草稿`：尚未完成截图、业务审核或 PDF 验证。

## 2. 每份 SOP 必须记录

- SOP 编号和标题。
- 适用岗位。
- 系统入口和所需权限。
- 版本日期。
- 对应系统发布版本或代码提交。
- 业务负责人和文档维护人。
- 最后实测日期。
- 前置条件和最终成功结果。
- 错误入口、危险操作、停止条件和升级对象。
- 替代的旧版本及被哪一版替代。
- HTML 源文件和 PDF 文件位置。

## 3. 标准内容

1. 封面：岗位、系统路径、版本和适用范围。
2. 先记住：3 至 5 条强制规则。
3. 完整流程图：从开始到最终验证。
4. 每个关键步骤一页真实系统截图。
5. 红框指出实际按钮、字段或状态。
6. 特殊情况：缺资料、权限不足、外部等待、退回修改和错误入口。
7. 常见错误。
8. 最终检查表。
9. 5 至 10 道知识检查题。
10. 一项培训账号实操任务和主管验收标准。

## 4. 发布门禁

SOP 只有同时通过以下检查才可以标记为“现行”：

- 业务负责人确认流程和责任边界。
- 使用正确角色账号走通完整流程。
- 截图来自当前系统，不包含无关桌面或敏感资料。
- PDF 页数、文字提取和关键按钮名称检查通过。
- PDF 全页渲染后无裁切、重叠、空白页或模糊截图。
- 总表中的版本、链接和替代关系已更新。

## 5. 系统改版后的处理

以下变化必须触发 SOP 复核：

- 页面入口或导航变化。
- 按钮、字段或状态名称变化。
- 角色权限变化。
- 新增强制前置条件或审批。
- 财务、课包、扣课、工资、合同或发布规则变化。
- 新增员工小程序流程并替代原网页操作。
- 家长可见范围、通知或隐私规则变化。

触发后先把状态改成“待复核”，避免员工继续把旧截图当作当前操作。

## 6. 文件管理

- 可维护源文件统一保存在 `docs/`。
- 正式 PDF 统一保存在 `output/pdf/`。
- 培训总入口统一保存在 `docs/培训中心/`。
- 旧文件不立即删除，通过总表标记“已替代”。
- 合同样板单独归入参考资料，不放在岗位必修 SOP 清单。
- 临时渲染、截图检查和测试 PDF 保存在 `tmp/`，不作为正式培训资料。
