# 小程序产品规划：家长安心看板

日期：2026-07-17

适用范围：博思学业管家家长端、员工端及对应 Miniapp API

状态：长期规划文档；每次小程序讨论和发布后持续更新

## 1. 产品目标

小程序不是后台功能的缩小版。家长端的首要任务，是用经过审核的事实持续回答：

1. 孩子现在整体怎么样。
2. 博思本周做了什么。
3. 当前哪里需要关注，以及团队正在怎么处理。
4. 下一步由谁负责、何时推进。
5. 家长现在是否需要配合。

产品目标是降低不确定性，而不是简单隐藏问题。任何关注事项都必须与已采取行动、负责人和下一节点一起展示。

## 2. 现有能力基线

当前家长端已经具备：

- 微信登录、学生绑定和多孩子切换。
- 首页、课表、课后反馈、财务、服务请求和微信订阅提醒。
- 普通课程、学业管理和全程托管三种服务定位。
- 本周课程完成情况、下一步、负责人、家长配合事项和最近服务动态。
- 正式全托管报告列表、详情、PDF、确认收到和报告问答。
- 家长关系权限、成年大学生授权和全托管发布状态隔离。

必须继续保留的安全边界：

- 家长只能查看已经授权且已发布的内容。
- 不返回内部备注、事实证据原文、专业判断过程、员工任务描述、草稿或撤回记录。
- 排课、扣课、课时包、财务、老师工资和合作方结算继续使用原系统逻辑。

## 3. 统一信息架构

微信原生底部导航保持五项静态结构，不引入高维护成本的自定义导航：

1. `首页`：状态、已完成服务、下一步、家长配合、最新报告和下一节课。
2. `服务`：本周服务汇总、负责人、正式报告、请求和最近服务记录。
3. `课表`：继续使用现有课表和课程详情。
4. `财务`：继续使用现有课时包、发票和收据信息。
5. `我的`：学生切换、绑定学生和退出登录。

服务请求不再占用一个底部导航位置，从首页和服务页进入。多孩子切换继续在“我的”保留，并在首页顶部提供快捷入口。

## 4. 家长首页标准

首页按以下优先级展示：

1. 当前学生、学校、年级和切换入口。
2. 家长可理解的状态：`进展稳定`、`需要关注`、`正在重点跟进`。
3. 状态解释；需要关注时必须说明团队正在跟进，不能只显示风险标签。
4. 本周课程、反馈和处理中请求的服务摘要。
5. 唯一最重要的下一步及计划日期。
6. 需要家长配合；无事项时明确显示“目前无需家长处理”。
7. 最新正式报告及待确认状态。
8. 下一节课、最新课后反馈。
9. 课时、提醒设置和其他次要信息。

首页不直接展示内部的“低风险/中风险/高风险”术语。剩余课时使用“小时+分钟”，不只显示分钟。

## 5. 服务进展标准

服务页固定分为：

- 当前服务与主要负责人。
- 本周服务：完成课程、课后反馈、处理中请求。
- 下一步：家长配合事项优先，其次是学生档案下一步、下一节课或处理中请求。
- 正式进展报告：直接进入报告列表并显示最新报告状态。
- 最近服务记录：只显示家长有权查看的课程、反馈、请求和已发布托管动态。

普通课程、学业管理和全托管共用一个页面，但文案和内容优先级不同，不能为普通课程家庭展示不存在的全托管承诺。

## 6. 正式报告标准

报告列表展示报告类型、期间、标题、摘要和 `待确认/已确认` 状态。

报告详情先展示：

- 本期结论。
- 已完成行动。
- 下一阶段计划。
- 学生需要完成。
- 家长需要配合。

学业进展、学校沟通、生活与状态、风险与专业判断、服务证据放在详细内容区。PDF 和确认收到作为固定底部操作，报告问答保留在正文之后。

## 7. 服务类型差异

### 普通课程

下一节课、课后反馈、剩余课时优先。服务页仍可使用，但不显示全托管报告承诺。

### 学业管理

本周学习进展、学习目标、负责人、下一步和阶段复盘优先。

### 大学前全托管

整体状态、学校沟通、学业进展、风险干预、生活协调、家长配合和正式报告优先。

### 大学阶段

保持轻量，优先展示正式报告、学业里程碑、实习就业或研究生准备。成年学生家长可见范围必须继续受明确授权控制。

## 8. 后续提醒规划

在微信公众平台确认模板后，独立增加：

- 正式报告已发布。
- 家长配合事项即将到期。
- 重大事项已有处理结果。

普通服务动态不逐条推送。建议节奏为每周摘要、月度/阶段报告和重大事项即时通知。

## 9. 员工端后续规划

员工小程序只承载现场高频操作，不复制完整后台：

- 快速新增服务跟进。
- 拍照或上传学校邮件、会议纪要、医疗、住宿等凭证。
- 完成全托管待办。
- 填写独立的家长可见摘要。
- 查看本周待跟进、月报到期和高风险学生。

报告编辑、审核和发布继续留在电脑后台，避免手机误操作。

## 10. 发布顺序

### 第一阶段：家长安心看板

- 调整底部导航。
- 重构首页和服务页信息层级。
- 优化报告列表和报告详情。
- 保持现有接口权限和业务写入不变。

### 第二阶段：全托管微信提醒

- 先确认微信模板和关键词映射。
- 增加报告、家长待办和重大结果提醒。
- 增加去重、授权额度和失败重试验证。

### 第三阶段：员工全托管快捷记录

- 增加员工端全托管只读工作队列。
- 再逐项开放受审计的跟进、附件和待办写入。

## 11. 验收标准

- 普通课程家庭不会看到虚假的全托管栏目。
- 全托管家庭可以从首页一层进入服务和最新正式报告。
- 家长无法读取草稿、内部备注或未授权大学报告。
- 多孩子切换、课表、反馈、财务、请求、PDF 和退出登录继续可用。
- 375px 至 430px 常见手机宽度无横向溢出、文字遮挡或按钮超出。
- 每次上线前完成小程序语法检查、发布审计、权限测试、后端测试和生产构建。
