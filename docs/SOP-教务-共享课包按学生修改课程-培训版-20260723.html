Academic Operations SOP / 教务培训流程

共享课包按学生修改课程
Change Course Per Student in a Shared Package

当兄弟姐妹或多名学生共用一个课时余额，但年级、学习内容或课程方向不同，教务可以只修改其中一名学生的未来课程。 系统会保留共享余额，不改其他学生，并把符合安全条件的已排、尚未开始的一对一课次同步到新课程。

适用角色教务 / Admin
入口Packages / 课时包
系统版本Release r282
版本日期2026-07-23

一句话答案

共享课包不再要求所有学生学同一门课。 课时余额仍然共用；教务在编辑课包时选择“要修改的学生”，再选择原课程、新课程和原因。 保存后只迁移该学生安全的未来一对一课次，其他共享学生保持不变。

SGT Manage 教务培训 SOP1 / 15

先记住这 6 条

  1. 共享的是余额，不是课程内容。不同年级、不同学习目标可以使用不同课程。
  2. 每次只处理 一名学生 + 一门原课程 + 一门新课程，不要一次混合多个学生。
  3. 已安排且尚未开始的安全一对一课次会同步修改；过去课程和已完成课程不改。
  4. 班课、已有签到/扣课/反馈的课次，以及无法唯一识别学生的课次不会自动改。
  5. 必须填写修改原因，并先读完系统预览数字，再点击 Update / 更新。
  6. 修改课程不会改变课时余额，也不会重写合同、发票、收据、老师工资或合作方结算。
绝对不要：为了让一个学生换课而直接修改整个共享班课的课程属性。班课属于全班，修改会影响同一节课里的其他学生。

教务最常见的使用场景

兄弟姐妹年级不同

同一个余额池，哥哥学习中学数学，妹妹学习低年级英文。

学生已进入国际学校

从“国际学校入学考试”转为“学科学习 / Academic Subject Bridging”。

学习目标发生变化

从考试备考切换到英语沟通、IB、IGCSE、A-Level 或大学学科。

先记住：余额共享，课程按学生管理2 / 15

完整操作流程

1. 找课包进入 Packages，搜索课包归属学生。
2. 核对课包确认课程、状态和剩余课时，点击 Edit。
3. 选学生在绿色区域选择本次要修改的学生。
4. 选课程选择原课程、新课程并填写原因。
5. 看预览核对自动修改、班课、保护和异常数量。
6. 保存复查点击 Update，再检查课表、提醒和其他共享学生。

操作前准备

必须确认的业务信息

学生姓名、当前学习内容、新学习内容、生效日期、是否已经安排未来课程、是否与兄弟姐妹共享课包。

必须确认的系统信息

课包仍为 ACTIVE、剩余课时正确、学生仍在共享学生名单中、原课程属于该课包可扣课范围。

推荐原因格式：学生姓名 + 原课程 → 新课程 + 生效原因 + 生效日期。 示例：Coco Xu：国际学校入学考试 → Grade 6 Math；已入读学校，转为六年级数学学科学习；自 2026-07-24 起。

先判断：普通课包还是共享课包

判断项目普通 / 单人课包共享课包
界面标题Course for this package and all not-started lessonsChange one shared-package student's future course
是否选择学生不需要，默认就是课包归属学生必须选择本次要修改的学生
课包主课程改为新课程保持不变，避免影响其他共享学生
新课程扣课范围新课程成为主课程新课程加入该共享课包的允许课程范围
未来课次该学生安全的一对一课次只处理所选学生安全的一对一课次
为什么共享课包不直接改主课程？ 因为主课程属于整个课包。如果兄弟姐妹学习内容不同，直接替换主课程会让另一个学生的课程显示和扣课范围一起被改变。 新功能把“余额归属”和“学生课程”分开处理。

本功能不处理的内容

不改余额

总分钟、剩余分钟、历史扣课流水不变。

不改财务文件

合同、发票、收据和付款状态不变。

不改历史

过去课次、完成记录、签到和反馈不被重写。

Packages / 课时包

操作：

  2. 搜索课包归属学生。
  3. 核对当前课程、类型、剩余课时、ACTIVE 状态。
  4. 点击该行 Edit / 编辑。

步骤 2：确认这是共享课包

Edit package / 编辑课包

打开编辑窗口后，看到绿色的“修改一名共享课包学生的未来课程”区域，说明系统已经识别到共享学生。

先核对：
  • 顶部 Student / 学生是课包归属人，不一定是这次要改课的学生。
  • Remaining / 剩余和 Total / 总量只读，本次操作不会改变余额。
  • 绿色说明明确写着：只改所选学生，其他学生保持不变。
图 2：共享课包必须在绿色区域操作。如果只看到“New course / 新课程”而没有学生选择框，当前记录不是共享课包。
步骤 2：识别共享课包编辑区域6 / 15

步骤 3：依次填写 4 个字段

Student + Source + Target + Reason
  1. Student to change / 要修改的学生：选择本次课程发生变化的学生。
  2. Current course to replace / 要替换的原课程：选择该学生现在使用的课程。
  3. New course / 新课程：选择以后课表和家长提醒应显示的新课程。
  4. Reason / 修改原因：写清楚原因和生效时间，不能留空。
图 3：示例选择 Eason Xu。Coco Xu 仍共享同一余额，但不会跟着改成 Eason 的课程。
原课程必须选对：系统只迁移“当前课程等于所选原课程”的未来课次。原课程选错，会导致预览数量为 0 或留下未修改课次。
步骤 3：填写学生、原课程、新课程和原因7 / 15

步骤 4：读懂系统预览

选择新课程后，系统会自动检查已排课次。请等待“Checking arranged lessons...”结束，再看四类数字。

预览项目会自动修改吗含义与教务动作
not-started 1-to-1 lessons
未开始一对一课次		 会 课次时间在现在之后、班级容量为 1、只关联该学生，且没有签到、扣课或反馈。保存后自动改为新课程。
group lessons
班课		 不会 同一节课属于多名学生，不能只为一人改。按“班课例外流程”处理。
attendance / feedback
已有签到或反馈		 不会 系统保护已有业务记录，避免签到、扣课、反馈和课程不一致。
ambiguous lessons
无法唯一识别学生		 不会 常见于一对一班级被错误关联多名学生。先检查班级和课次学生关系。
预览数字不是全部为 0 才能保存。 系统会只修改安全课次，并保留例外课次不动。教务需要记录未自动处理的数量，保存后逐项检查。
Preview unavailable / 预览失败：不要盲目保存。刷新页面重试；仍失败时，把课包归属人、所选学生、原课程、新课程和截图交给系统管理员。
步骤 4：理解四类预览数字8 / 15

步骤 5：点击 Update / 更新

  1. 再次核对学生、原课程、新课程和原因。
  2. 记录预览中的自动修改数、班课数、保护数和异常数。
  3. 滚动到窗口下方，点击 Update / 更新。
  4. 等待窗口关闭或页面出现 Saved / 已保存，不要连续点击。
保存成功后，系统会自动完成： 所选学生的安全未来一对一课次改为新课程；共享课包余额不变；其他共享学生不变； 新课程加入该课包可扣课范围；课程变更原因和每个迁移课次写入审计记录。

保存失败时的原则

页面仍停留在窗口

先读红色错误文字，不要重复点 Update。修正字段后再提交。

提示已有相同未来课次

系统没有保存任何变更。先处理重复排课，再重新执行课程修改。

提示学生未关联课包

确认学生仍是课包归属人或共享学生；不要在同一次保存中把该学生从共享名单移除。

页面超时或断开

重新打开课包先检查是否已保存，再决定是否重做，避免重复操作。

步骤 5：保存与失败处理9 / 15

共享学生年级不同、内容不同：正确做法

示例：Coco 与 Eason 共用课包

Coco 学 Grade 6 Math，Eason 学 Grade 3 English。两人继续共用一个剩余课时余额，但课程、老师和未来课表可以不同。

每次操作只改一个人

先处理 Coco 并保存、复查；如 Eason 也要改，再重新打开同一课包单独处理 Eason。

项目CocoEason共享课包
学习课程Grade 6 MathGrade 3 English允许两门课程扣课
未来课表只显示自己的数学课只显示自己的英文课不会把两人的课程混在一起修改
家长提醒显示 Coco 对应课程显示 Eason 对应课程待发送提醒按各自课次重建
课时余额继续从同一个共享余额扣减总量和剩余量不因改课而变化
推荐课程名称：课程应表达学生实际学习内容，例如 Grade 6 Math、IGCSE Chemistry、Academic English。 不要只用过于宽泛的旧名称，否则家长提醒和课表仍然不够准确。
不同年级、不同课程的共享课包处理10 / 15

班课与保护课次：例外处理 SOP

例外类型为什么不自动改教务处理方法
未来班课 同一班课关联多名学生，课程属性属于全班。 检查班级名单。全班都转课时走班级/排课流程修改；只有一名学生转课时，为该学生安排新的独立班级或一对一课次。
已有签到、扣课或反馈 这些记录已经进入教学或账务历史，改课程会破坏一致性。 不要通过课包编辑强改。确有录入错误时，走签到/扣课修复流程并保留说明。
无法唯一识别学生 容量为 1 的班级或课次却关联多名学生，系统无法判断应改谁。 打开班级和课次，核对学生关系；修正后重新预览。不能确认时停止操作并升级管理员。
已经开始或时间已过去但未签到 本功能只迁移当前时间之后的课次。 先确认真实上课情况。已上课按签到/反馈流程处理；未上课按课次调整流程重新安排。
停止线：无法确认这节课属于谁、是否已经上课、是否已经扣课时，不要继续修改。先向老师或教务负责人确认。
班课与受保护课次的人工处理11 / 15

“Less-common fields / 不常改字段”怎么处理

Normally leave unchanged

正常的按学生换课不需要手工改共享学生或共享课程。系统会在保存时自动把新课程加入允许扣课范围。

图 4：所选学生必须继续留在共享学生中。不要为了换课程把学生从共享名单删除。
只有以下情况才打开这里：经管理确认要新增/移除共享学生，或需要整理历史共享课程范围。 这属于课包结构调整，不是本次按学生改课的常规步骤。
高级字段：正常换课不要手工调整12 / 15

保存后必须做的 5 项复查

  1. 课包：重新打开编辑窗口。共享课包主课程可保持原样，新课程应进入允许扣课范围。
  2. 所选学生课表：检查未来一对一课次是否显示新课程，老师、日期和时间是否正确。
  3. 其他共享学生：抽查兄弟姐妹未来课表，确认没有被连带修改。
  4. 历史课程：过去已完成、已签到、已扣课或已有反馈的课次应保持原课程。
  5. 余额：总课时、剩余课时和历史扣课流水应与修改前一致。

家长提醒与课表显示

提醒状态系统处理教务动作
尚未发送的 24 小时小程序提醒旧待发记录作废，并按新课程重建抽查一条待发提醒，确认学生和课程名称正确。
已经发送给家长的提醒不会静默改写已发消息如原消息课程错误，使用现有家长沟通修正流程补发说明。
以后打开的学生课表安全迁移的未来课次显示新课程从学生视角检查，不要只看课包主课程。
推荐：修改完成后，把“所选学生课表 + 另一名共享学生课表”并排核对一次，这是发现连带错误最快的方法。
