# SGT 微信小程序发布台账

固定从 GitHub 的 `codex/miniapp-releases` 分支处理小程序版本。每个版本目录保存打包源码提交、目标 AppID、API、逐文件 SHA-256 和开发上传回执。标记 `miniapp/v<版本>` 直接指向对应源码，换电脑后可用同一标记重建。日常业务代码先进入 SGT 生产源码分支，开发上传、设为体验版、提审和正式发布是四个不同动作。

## 每次上传

1. 在发布分支执行 `git fetch origin`，先同步 `origin/codex/miniapp-releases`，再合并 `origin/feat/strict-superadmin-availability-bypass`。如版本字段冲突，保留最新生产源码其余内容，并在下一步设置新版本。用独立工作目录，避免使用旧的微信开发者工具项目。
2. 运行 `npm run miniapp:upload-test -- --status` 查共享台账，并核对微信公众平台版本管理是否有台账外的版本。若有，先核对并补录实际版本和证据，确保新版本大于所有已占用版本。只改 `miniapp/boss-academic-parent/utils/config.js` 的 `clientVersion`，提交后执行 `npm run miniapp:upload-test -- --check`。脚本校验最新生产源码、版本号、上一包文件路径、配置及页面文件，同时列出改动。确实要删除或合并旧页面时，先记录原因、替代入口和对应回归结果，再审核变更上传检查规则。
3. 微信开发者工具登录后，运行 `npm run miniapp:upload-test -- --notes "简述本次功能和修复"`。脚本先向 GitHub 原子写入版本预留和源码标记，再上传已提交的文件。收到开发者工具成功回执后，自动提交并推送回执。成功后用 `--status` 核对远端台账。
4. 需要发给员工时，由有权限的同事在微信公众平台选择已验收的同一版本设为体验版。按当次功能走查，优先验证员工登录、HR 假期和工资单、教务改课和通知，以及家长入口。每次实际确认体验、提审或正式发布状态后，更新 `channels.json` 的对应项，填写 `version`、`verifiedAt`、`verifiedBy`、`status` 并提交到发布分支。状态曾变更的历史可从 Git 查看。

## 上传中断或回执未入库

- `--status` 显示预留而没有回执时，先对照微信后台和本机 `output/miniapp` 核实。若回执提交已在本地，只需检查后推送该提交。若后台已确认上传但回执未提交，按真实证据补齐版本目录中的 `receipt.json`，写明对应源码、确认时间和包大小，提交推送。
- 如果确认该上传未成功，将原预留版本标为作废，保留其源码标记。在同一版本目录增加 `resolution.json`，填写 `version`、`status: "abandoned"`、`verifiedAt`、`verifiedBy`、`reason`，提交推送。再用更高的版本号重新打包。若结果还未查明，保留预留状态。
- 正式版出问题时，通过微信后台核实可用回退版本或用源码标记定位修复起点。新修复仍从最新生产源码和更高的版本号进入同一流程。
