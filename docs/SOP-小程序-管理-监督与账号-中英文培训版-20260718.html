管理原则 / Management principles

01
中文
  1. 先看“统一待办”、需更正、逾期和红色数字。
  2. 管理监督，不代替教务逐条发送。
  3. 老师原文与家长展示版分开。
  4. 反馈“审核发布”和“人工发家长微信群”是两个独立完成步骤。
  5. 错误通过更正，不删除记录。
  6. 双身份使用两个账号并从账号管理切换。
English
  1. Start with priority and red counters.
  2. Management supervises without replacing operations.
  3. Keep teacher original and parent-facing content separate.
  4. Track automatic and manual delivery separately.
  5. Correct errors without deleting history.
  6. Use separate accounts for dual roles.

统一待办与全部工单 / Unified Tasks and All Tickets

02A
中文
  1. 统一待办只显示当前管理账号需要立即处理的事项。
  2. “工单待处理”数字进入“全部工单”，数字和列表使用同一统计范围。
  3. 全部工单同时包含“家长请求”和“自营学生”来源，可按负责人、类型、状态审查。
  4. 若列表数量较少，先下拉刷新并清除筛选，不要把筛选后的条数误认为数据丢失。
  5. 抽查没有负责人、已逾期、等待补充和高风险更正任务。
English
  1. Unified Tasks shows only actions required from the active management account.
  2. Ticket Tasks opens All Tickets; counter and list use the same scope.
  3. All Tickets includes Family Request and Self-operated Student sources with owner/type/status filters.
  4. If the list looks short, refresh and clear filters before treating it as missing data.
  5. Review unowned, overdue, waiting-for-info, and high-risk correction items.
完成标准 / Done：所有到期或高风险项都有负责人和下一步，数字能由当前筛选解释。 / Every due or high-risk item has an owner and next action, and counters reconcile with filters.

监督家长沟通任务 / Monitor communication tasks

04
中文
  1. 打开“家长沟通与通知”。
  2. 先筛“课程变更补发 / 待补发”，再看全部待处理。
  3. 检查是否未领取、负责人是否均衡。
  4. 课后反馈必须抽查两步：第 1 步已审核发布；第 2 步已人工发送到家长微信群。
  5. 抽查自动与人工状态、群名/对象和截图证据。
  6. 超时任务立即转交或升级。
English
  1. Open Parent Communication.
  2. Filter Corrections first, then all open tasks.
  3. Check ownership and workload balance.
  4. For lesson feedback, verify both Review & Publish and Manual Send to Family WeChat Group.
  5. Sample automatic/manual status, destination, and evidence.
  6. Transfer or escalate overdue tasks.
红框：状态、负责人、自动/人工结果和发送动作。 / Status, owner, delivery channels, and evidence.

监督课程变更补发 / Supervise course change resends

04B
管理检查重点
  1. 确认卡片明确写出取消、改期、换老师、换地点或多项变更。
  2. 原安排与当前安排必须可以直接比较；取消必须写“暂无替代课程”。
  3. 检查原提醒发送人/时间和课程变更人/时间，判断责任链是否完整。
  4. 确认教务把补发内容发到原家长群或老师微信，而不是只点系统完成。
  5. 没有微信发送截图的任务不得完成；异常应退回负责人补证。
Management checks
  1. The card must name the actual change: cancellation, reschedule, teacher, location, or multiple fields.
  2. Previous and Current must be directly comparable; cancellation must state no replacement.
  3. Review the original sender/time and lesson changer/time for accountability.
  4. Verify the follow-up was sent to the original WeChat destination, not merely completed in-system.
  5. Completion requires a WeChat evidence screenshot; return exceptions for evidence.
生成规则：原提醒未发送 → 直接更新原提醒；原提醒已发送 → 新建课程变更补发。这样既避免无意义的重复任务，也防止微信群继续使用旧安排。 / Unsent originals are updated in place; only already-sent originals create a resend task.

管理审批中心 / Management Approval Center

07A
中文
  1. 从统一待办或首页进入“管理审批中心”。
  2. 先核对申请人、学生/课程、金额或变更内容、附件和历史记录。
  3. 资料齐全且权限允许时在手机端批准或驳回，并写清原因。
  4. 复杂财务对账、批量调整和高风险权限变更继续在网页版处理。
  5. 不要为了清空数字批准缺资料事项。
English
  1. Open Management Approval Center from Unified Tasks or Home.
  2. Verify requester, student/lesson, amount or change, evidence, and history.
  3. Approve or reject eligible mobile items with a clear reason.
  4. Use the web system for complex reconciliation, bulk adjustments, and high-risk access changes.
  5. Never approve incomplete work merely to clear a counter.
停止点 / Stop：对象、金额、证据或权限任一不清楚时先退回补充。 / Return for clarification whenever recipient, amount, evidence, or authority is unclear.

学生 360°、新咨询与操作纠正 / Student 360, leads, and correction

07B
中文

学生 360°：集中核对家长联系方式、课包余额、未来课程、未完成工单和历史反馈，用于判断问题是否跨模块。

新咨询快速录入：尚未成为现有学生的新家庭先录咨询，填写来源、意向、下次跟进时间和证据；需要排课时再转为工单。现有学生请求直接录工单。

操作日志与纠正：查看谁在何时做了什么；发现错误从原操作发起纠正工单，禁止覆盖或删除原记录。

English

Student 360: review contacts, package balance, future lessons, open Tickets, and feedback history in one place.

New Lead Intake: capture a new family’s source, intent, next follow-up, and evidence; convert to a scheduling Ticket when appropriate. Existing students use Tickets directly.

Audit & Correction: see who did what and when; create a correction Ticket from the original operation without overwriting history.

分流规则：“还不是学生”走新咨询；“已经是学生且提出服务请求”走工单。 / New prospect → Lead; existing student service request → Ticket.

错误事件处理 / Incident response

08
中文
  1. 先停止旧信息传播。
  2. 确认正确课表/反馈。
  3. 创建并发送更正。
  4. 保留旧记录和新截图。
  5. 网页版审计日志复原时间线。
  6. 分类根因：数据、流程、权限、培训或系统。
English
  1. Stop stale information.
  2. Verify correct schedule/feedback.
  3. Create and send correction.
  4. Preserve original and correction evidence.
  5. Use web audit logs for the timeline.
  6. Classify root cause.
禁止：删任务、改数据库掩盖、换账号重做、只在微信口头处理。 / Never erase, hide, switch identities to redo, or resolve only verbally.
