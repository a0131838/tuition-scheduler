What This Function Is For / 这个功能用来做什么

Short answer: use this when a parent asks GT to support school applications, including AEIS/S-AEIS and Singapore international school applications. This is a service agreement and finance billing workflow. It is not a lesson package workflow.
一句话：家长需要 GT 协助申请学校时使用，包括 AEIS/S-AEIS 和新加坡国际学校申请。这是服务协议 + 财务收款流程，不是课时包流程。

Must-Know Rules / 先记住这些规则

  1. Use the separate service billing case. The system creates or reuses School Application Service; do not use English/Math lesson packages.
    必须使用独立服务收款 case。系统会创建或复用 School Application Service；不要使用英语/数学课包。
  2. No lesson hours are added or deducted. This workflow only handles agreement, invoice, payment proof, receipt, and finance approval.
    不会增加或扣减课时。本流程只处理协议、invoice、付款凭证、receipt 和财务审批。
  3. Parent info link comes before formal signing. Use it when parent name/phone/email/address/ID needs confirmation.
    正式签字前可先发家长资料链接，用于确认家长姓名、电话、邮箱、地址、证件号等。
  4. Signing must be handwritten. Parent now sees the full agreement and must sign in the handwritten signature box.
    签署必须手写。家长会看到完整协议，并必须在手写签名框签名。
  5. Void is not deletion. Delete is only allowed for voided records with no invoice. Invoice-linked records stay for audit.
    作废不等于删除。只有作废且无 invoice 的记录可删除；已关联 invoice 的记录必须保留审计。
Stop and ask Management if: the parent wants a special refund rule, the school list is unclear, fees do not match the agreement, or the wrong student was selected.
以下情况先停：家长要求特殊退费规则、学校名单不清楚、费用和协议不一致、或选错学生。

Step 3: Fill Required Draft Fields / 填写草稿必填项

Draft Guard

The form now shows required fields and blocks obvious missing data before submitting. This reduces the old issue where reminders could refresh the page and lose unsaved input.
现在表单会显示必填项，并在提交前拦住明显缺项，减少以前提醒后刷新页面导致未保存内容丢失的问题。

Fill at minimum / 最少要填： parent name, agreement date, first school/application, and at least one fee amount so total is greater than 0.
至少填写：家长姓名、合同日期、第一所学校/申请项目，以及至少一个费用金额使总额大于 0。

Step 7: Parent Handwritten Signature / 家长手写签名

Required Signature

The parent must complete the handwritten signature box. The system will reject signing if there is no handwritten signature image.
家长必须完成手写签名框。如果没有手写签名图片，系统会拒绝签署。

Parent action / 家长操作： fill signer name, optional email/phone, tick the confirmation checkbox, draw signature, then click Sign agreement / 签署协议.

After submit / 提交后： the signature image is stored, the signed PDF includes the signature, and the system prepares the invoice for Finance.

Step 9: Void and Delete / 作废与删除

Correction

If the record is wrong, use Void / 作废. Only a voided record without invoice can be deleted. Signed or invoice-linked records should stay for audit history.
记录错误时使用 Void / 作废。只有作废且无 invoice 的记录能删除。已签署或已关联 invoice 的记录应保留审计历史。

Invoice-linked records cannot be cleaned like test drafts. If invoice or receipt is wrong, use Finance/Management correction route.
已关联 invoice 的记录不能像测试草稿一样清理。 如果 invoice 或 receipt 错误，走财务/管理修正流程。

Common Mistakes / 常见错误

  • Creating service on the wrong student. Always start from the correct student profile.
    在错误学生名下创建服务。必须从正确学生详情页进入。
  • Sending sign link before parent info is confirmed.
    家长资料未确认就发正式签字链接。
  • Leaving total amount as 0, causing save/sign preparation to fail.
    总金额为 0，导致保存或准备签署失败。
  • Using the wrong school grade wording, especially British Year levels.
    学校年级叫法错误，尤其是英系 Year。
  • Thinking parent click confirmation is enough. It now requires handwritten signature.
    以为家长点击确认就够；现在必须手写签名。
  • Deleting or trying to hide signed/invoiced records.
    删除或试图隐藏已签署/已开票记录。
