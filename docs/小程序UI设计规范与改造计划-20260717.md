# 小程序 UI 设计规范与改造计划

日期：2026-07-17

## 1. 视觉主张

小程序采用“专业教育服务工作台”方向：暖白作为主画布，深灰承载主要信息，品牌橙只强调主操作、当前状态和关键入口。员工端保持紧凑、便于扫描；家长端保持舒适、结论优先。

不采用营销式大标题、装饰性渐变和卡片拼贴。每个首屏只回答三件事：当前状态、最重要的下一项任务、进入完整工作区的入口。

## 2. 四类角色信息架构

### 管理

- 首屏先显示逾期排课、提醒异常和开放工单。
- 指标只保留今日课程、家长请求、排课逾期。
- 入口按课程工作台、排课协调、家长请求、学生排课、提醒异常排列。

### 教务

- 首屏先显示待处理家长请求，再补充开放排课和需关注学生。
- 工作入口强调课程、排课、家长沟通和代录服务请求。
- 所有结果继续进入原有工单或排课工作流，不在首页新增业务写入。

### 老师

- 首屏固定显示下一节课；点击进入原课程详情完成点名、反馈或调课申请。
- 指标只保留今日课程、本月完成和报销处理中。
- 教学事务包含课表、可用时间、请假调课、报销和教学记录。

### 家长

- 首页继续按“状态、已交付、下一步、需要配合、正式报告”组织。
- 家长只看已授权和已发布内容，不显示内部草稿、员工讨论或敏感信息。
- 页面用更舒适的留白和层级，不增加无业务价值的功能入口。

## 3. 共享视觉规范

- 页面背景：`#F6F4F1` 暖白。
- 主文字：`#202328`，标题使用更深的 `#17191D`。
- 品牌橙：`#EC5E0A`，继续用于原生导航、主按钮和活动状态。
- 风险红只用于逾期和需要立即关注的状态。
- 基础圆角：输入与次级按钮 `12rpx`，内容容器 `14-16rpx`，重点任务面板 `18rpx`。
- 间距采用 8rpx 倍数，页面左右安全边距为 `30rpx`。
- 常规列表以分隔线组织；只有“重点任务、状态、报告”等需要整体点击或独立语义的内容使用容器。

## 4. 交互规范

- 页面进入使用 220ms 的轻量淡入上移，不阻塞操作。
- 重点任务面板和主按钮提供轻微缩放反馈。
- 动态角色标题、状态和计数在 JavaScript 中预先计算，避免复杂 WXML 表达式导致微信渲染兼容问题。
- 列表行保持不少于 88rpx 的可点击高度；本轮员工首页使用 112rpx 行高。
- 下拉刷新继续使用原有数据接口；不增加自动轮询。

## 5. 分阶段改造

### 第一批：角色首页与视觉底座（本次）

- 统一小程序全局背景、圆角、输入、按钮、动效和内容容器。
- 员工首页按 ADMIN、CS、TEACHER 显示不同重点任务与入口。
- 老师首页读取现有老师工作台数据，显示下一节课并进入原课程详情。
- 家长首页继续复用现有安心看板逻辑，优化标题、状态容器和报告入口层级。

### 第二批：高频执行页面

- 老师：课程详情、点名、课后反馈、可用时间。
- 教务：月历、排课协调、家长请求、学生排课。
- 管理：异常列表、提醒关注和跨角色查看体验。

### 第三批：列表、详情与表单收口

- 统一空状态、错误提示、筛选、搜索、表单字段、状态标签和底部主操作。
- 完成 30 个原生页面的视觉审计和真机逐页验收。

## 6. 安全与非目标

- 本轮只修改 `miniapp/boss-academic-parent/**`、测试和文档。
- 不修改 `app/admin/**` 或任何网页版页面。
- 不新增或修改 API、数据库、权限、排课、考勤、课包、结算、工资和财务逻辑。
- 不把员工端权限扩大给其他角色；入口是否显示继续由现有接口能力决定。

## 7. 第一批验证

- 员工首页 JavaScript 语法检查通过。
- 角色首页、登录入口和月历待排课队列共 11 项专项测试通过。
- 30 页小程序发布审计通过，AppID、正式域名、基础库、Source Map、模拟登录和搜索保护符合要求。
- 全量小程序测试、后端回归、TypeScript、生产构建和微信开发者工具编译在发布前继续执行并记录。
