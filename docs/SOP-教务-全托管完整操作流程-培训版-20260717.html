Academic Operations SOP / 教务培训流程

全托管完整操作流程
从逐一启用学生到家长交付闭环

适用于大学前学业管理与全方位托管。目标不是增加消息数量，而是用真实证据、专业判断、明确行动、正式报告和及时风险处置，让家长持续看见服务价值。

先记住：6 条不能错的规则

  1. 学生必须由管理者主动选择加入全托管，不能因为出现在候选名单中就自动建立项目。
  2. 先确认服务类型和合同范围，再勾选服务；大学前学业管理与全方位托管不能混为一套默认承诺。
  3. “已跟进”不算交付。至少要有课程、老师反馈、学校材料、确认记录、完成结果或结构化跟进之一。
  4. 高风险与重大风险立即进入 Operations / 风险、代班与复盘，不能等到月底写报告。
  5. 正式报告必须经过 DRAFT → SUBMITTED → APPROVED → PUBLISHED，内部备注永远不发给家长。
  6. 每天先看 Quality dashboard / 质量工作台，把红色超时处理完，再做普通跟进。
禁止：不要制造焦虑、夸大风险、用大量无价值打卡代替交付，也不要把未经核实的员工讨论写进家长报告。

步骤 1：进入全托管并选择学生

Full Care / 全托管
操作：从完整后台侧栏进入 Full Care；先用姓名、学校或年级搜索；选择学生后才建立项目。已有项目的学生直接点击姓名进入。页面上方 Students / Quality 是全托管内部导航。
图 1：左侧完整后台导航仍然保留且全托管高亮；正文同时显示学生项目和质量工作台入口。培训演示学生不是固定名单。

步骤 2：创建项目前的业务判断

大学前学业管理

以课程规划、老师反馈、学习进度、考试作业、补习和学校学业沟通为主。不要默认承诺生活现场服务。

大学前全方位托管

除学业外，根据合同加入医疗陪同、重要交通、寄宿家庭、假期照护、签证行政协助等。

创建时逐项确认

  1. Program / 服务类型：选择与真实合同一致的项目。
  2. Service scope / 服务范围：只勾选已承诺内容；第三方费用、医疗诊断、移民法律意见和无限现场支持不自动包含。
  3. Case owner / 总负责人：当前通常为 Jasmine。
  4. Reviewer / 月报审核人：zhao hongwei。
  5. Start date / 开始日期：使用真实服务起始日，不倒填。
无陪读不等于无限服务：现场支持仍按合同、风险等级、工作时间和第三方费用规则执行；不确定时先停止并让管理者确认。

Project overview / 项目总览
启用前检查：项目状态、服务范围、Jasmine 的角色、zhao hongwei 的 REVIEWER / EXECUTIVE_OWNER 是否完整。
图 2：运营闭环、范围、负责人、正式报告和日常跟进都从学生项目页进入。

步骤 4：启用前建立阶段计划

字段正确写法错误写法
Period / 阶段“入学后 30 天适应期”“7 月学业稳定期”“长期跟进”
Baseline / 基线事实：当前成绩、出勤、学校反馈、已知风险“基础一般”
Goals / 目标明确结果和时间，例如两次测评按时完成“提升成绩”
Success criteria / 标准可以检查的完成条件“家长满意”
Action plan / 行动谁、何时、做什么、证据在哪里“持续关注”
启用条件：负责人明确、范围明确、阶段目标明确、家长权限明确，并且团队有能力持续维护。否则保持 DRAFT，不要为赶进度强行 ACTIVE。
每日打卡：只在刚到新加坡、失联、健康/行为/住宿高风险或合同明确约定时短期启用；记录目的、频率、开始和结束日期，风险解除后降频。

步骤 5：日常交付怎么记录

Update / 跟进

写事实、专业判断、已采取行动、结果验证、下一步和负责人。

Task / 待办

凡是还没完成的动作，都要有负责人和截止时间；完成时写结果证据。

Evidence / 证据

上传学校邮件、会议纪要、成绩、确认文件等；敏感原件设为内部。

一条合格跟进的模板

  1. Facts / 事实：谁在什么时候提供了什么信息。
  2. Judgement / 判断：正常、需观察还是需要介入，理由是什么。
  3. Action / 行动：团队已经做了什么。
  4. Result / 结果：对方是否确认、事情是否真的完成。
  5. Next / 下一步：负责人、截止时间和下一证据节点。
家长可见摘要：必须单独写经过核实的公开版；不要直接复制内部备注、医疗原件、寄宿家庭隐私或学生依法/依约应保密的信息。

步骤 6：生成正式月报

Formal reports / 正式报告
操作：项目页展开 Create report draft；选 MONTHLY、报告期间、开始和结束日期；系统从课程、反馈、跟进和证据形成可编辑草稿。
图 3：已发布报告显示状态、家长查看人数和打开入口。
系统会阻止：没有任何真实来源、仍保留“请负责人补充”占位文字、必填结论或下一步为空的报告提交。

步骤 7：写成家长真正需要的报告

Conclusion → Evidence → Action
每份报告必须回答：现在怎样、证据是什么、哪些正常/有风险、团队做了什么、接下来谁在何时做什么、家长是否需要配合。
图 4：家长看到正式栏目和审核后的 PDF；内部备注不进入页面、API 或 PDF。

步骤 8：审核、发布和撤回

状态谁操作允许动作注意
DRAFT / RETURNED负责人编辑并提交退回后先读 Review note
SUBMITTEDzhao hongwei / 指定审核人批准或退回退回必须写原因
APPROVED审核人发布给家长发布前再次核对家长可见内容
PUBLISHED审核人下载 PDF 或撤回已发布内容不能直接改写
REVOKED管理者保留审计修正应建立新报告，不覆盖历史
发布后不是结束：质量工作台会继续追踪 3 天未查看、7 天未确认和家长提问。
大学生：报告发布和读取还必须满足学生授权为 GRANTED/LIMITED，且授权栏目包含 formal_reports；未授权时不能用家长焦虑作为越权理由。

步骤 9：家长报告问答闭环

Parent miniapp + Admin reply
家长端：打开已发布报告 → 在“报告问答”输入问题 → 提交。系统自动给总负责人建立 HIGH、24 小时到期待办。
图 5：管理端在报告底部正式回复；回复后关联待办自动完成，家长查看后可点“问题已解决”。
回复标准：只回答已核实信息；需要内部确认时先建立待办，不要猜。紧急安全风险不能只在问答里回复，必须同时升级风险。

步骤 10：每天先看质量工作台

Quality dashboard / 质量工作台
建议顺序：响应超时 → 重大/高风险 → 家长提问超时 → 报告逾期/待审核 → 逾期待办 → 未查看/未确认 → 代班与复盘。
图 6：工作台只列异常和需要行动的事项，不要求员工在多个项目间逐个寻找。

步骤 11：风险升级与响应时限

Operations → Risk escalation
图 7：登记风险时写事实、立即行动、主负责人和备份负责人；超过首次响应时限自动标红。

风险等级与处理规则

等级首次响应 SLA例子状态路径
CRITICAL / 重大30 分钟人身安全、急诊、警方、失联、住宿安全OPEN → ACKNOWLEDGED → MONITORING/RESOLVED → CLOSED
HIGH / 高2 小时当天截止、严重出勤/成绩、重大住宿或签证问题必须指定不同的备份负责人
MEDIUM / 中24 小时需要尽快介入但不危及当天安全确认后持续观察或解决
LOW / 低72 小时一般观察项和轻微偏差按计划处理，不长期悬空
非工作时间现场支持：人身安全、急诊、警方、失联、住宿安全或当天无法延后的重大交通可启动；普通咨询、材料提醒和可延至工作日事项不属于紧急现场支持。
关闭条件：不能只点 RESOLVED。必须写 Resolution evidence / 解决证据；确认结果稳定后再 CLOSED。

步骤 12：Jasmine 缺席时安排代班

Backup coverage and handover
图 8：记录原负责人、代班人、起止时间、原因、交接摘要和关键截止日；同一项目不能重叠安排有效代班。

代班交接最少包含什么

Handover summary / 交接摘要

学生当前状态、未结风险、学校与家长沟通、报告进度、哪些事项不能遗漏。

Critical actions / 关键事项

逐项写负责人、截止时间、需要的结果证据，以及出现什么变化要升级。

  1. SCHEDULED：安排已保存，但代班尚未开始。
  2. ACTIVE：代班人正式接管，质量工作台显示进行中。
  3. COMPLETED：原负责人恢复，代班事项已交回并确认。
  4. CANCELLED：计划取消但保留历史，不直接删除。
不要只写“帮忙看一下”：没有截止时间和关键事项的交接等于没有交接。重大/高风险还应在风险事件中单独存在。

步骤 13：阶段结束或续费前做服务价值复盘

Service value review
图 9：复盘必须区分原目标、实际交付、学生变化、证据和下一阶段；内部续费备注不会发给家长。

服务价值复盘怎么写

栏目要回答的问题
Goals这个周期原来承诺解决什么，不事后改目标。
Delivery团队实际完成了什么，不用“沟通很多次”代替结果。
Outcomes学生、学校或家长发生了什么可观察变化。
Evidence课程、反馈、学校材料、会议、完成记录在哪里。
RecommendationCONTINUE、EXPAND、ADJUST、COMPLETE 或 HOLD，并说明原因。
Next stage下一阶段目标、动作和检查点。
Internal commercial note仅内部：续费沟通准备、合同边界和资源安排。
状态：DRAFT 可编辑；SUBMITTED 等待管理者；APPROVED 表示管理者已确认。复盘不是家长月报的替代品。

建议工作节奏

每天

打开质量工作台；处理红色超时；核对当日截止待办；重大变化立即升级。

每周

核对学生状态、老师反馈、学校节点和未结待办；补齐证据；更新阶段计划进度。

每月/每阶段

生成正式报告、审核发布、追踪家长查看与问答；阶段末完成服务价值复盘。

家长可以看什么

默认可见：已发布报告、公开版托管动态、课程出勤概况、老师反馈、下一步、家长配合事项、服务请求进度。
默认不可见：内部备注、未核实判断、员工讨论、第三方隐私、医疗原件、寄宿家庭敏感信息、未批准或已撤回报告。
解决家长焦虑的方法：稳定、及时、可验证地回答“现状、证据、判断、行动、下一步”，不是承诺所有事情都没有风险。

异常与停止规则

找不到学生

回 Students 核对真实档案，不要创建重复学生。

服务范围不清

保持 DRAFT，核对合同和管理决定，不要先全勾。

没有证据

先补课程、反馈、学校材料或结果记录，不能用空泛文字提交报告。

家长追问未核实

回复“正在核实”前先建立责任待办；获得事实后再正式回复。

风险已经超时

立即确认 ACKNOWLEDGED 并执行行动；不能为了消除红色直接点解决。

已发布报告有误

由审核人撤回并记录原因，建立修正版；不要覆盖历史。

必须找管理者：涉及人身安全、医疗判断、警方、法律/签证意见、合同外费用、无限现场支持、成年学生授权冲突或信息披露争议。
