一句话标准

全托管不是“记备注”：每个学生都要有明确范围和负责人；每次服务都要留下事实、专业判断、行动、结果和下一步；每个行动都要到人、到时、可验收。

当前第一版能做什么

建档与责任

选择现有学生，确定服务类型、开始日期、总负责人、月报审核人和服务范围。

计划与证据

建立阶段计划；记录学习、学校、生活、家长、风险、申请和职业事项。

行动与验收

把下一步转成待办，跟踪负责人、截止时间、状态和完成凭证。

独立边界：全托管模块不会修改排课、课时包、出勤扣课、合作方结算、发票收据或老师工资。

先记住：8 条硬规则

  1. 只有 Admin / Manager 可以建立项目、修改服务范围和负责人。
  2. CS + CARE 权限只能看到自己被分配的学生，可记录跟进、计划和待办。
  3. 新项目永远先建立为 DRAFT / 待启用，核对范围与责任人后再改为 ACTIVE。
  4. 事实与判断必须分开写；不能只写“已沟通”“已处理”“情况正常”。
  5. 填写“下一步”时必须填写截止时间；HIGH / CRITICAL 还必须指定负责人。
  6. 汇报范围选 PARENT / 家长摘要时，必须另外填写家长可读摘要。
  7. 待办改为 DONE时必须填写完成结果；WAITING_EXTERNAL 必须设置下次跟进时间。
  8. COMPLETED / CANCELLED 关闭后不能继续新增记录或重新配置，关闭前必须由负责人复核。

完整工作流

1. 开权限Admin 为执行人员勾选 CARE。
2. 建草稿搜索学生，选服务类型、范围和责任人。
3. 核对启用确认合同范围后 DRAFT → ACTIVE。
4. 建阶段计划写清基线、目标、完成标准和行动。
5. 留证据记录事实、判断、行动、结果和对外摘要。
6. 跟待办下一步到人到时，等待外部也要再次跟进。
7. 月度复核核对证据、风险和完成结果，准备家长汇报。

每日工作

  • 当天重要学校、学习、生活或家长事项，当天录入。
  • 高风险事项必须当天明确负责人、下一步和截止时间。
  • 已完成行动当天补写结果，不把“已做”当结果。

每周与每月

  • 每周检查未完成、WAITING_EXTERNAL、BLOCKED 和逾期待办。
  • 每月按阶段计划复盘目标，整理家长摘要和下一阶段重点。
  • zhao hongwei 最终审核后再对外发送正式口径。
交付公式：事实证据 + 专业判断 + 已采取行动 + 结果验证 + 明确下一步 = 一条可审计、可汇报的服务交付记录。

步骤 4：核对档案并启用项目

DRAFT → ACTIVE
图 4：顶部看状态和指标，中部核对服务范围与责任人，左侧是证据，右侧是待办。
启用前核对：学生正确、服务类型正确、开始日期正确、总负责人正确、审核人正确、合同范围一致。全部正确后选择 ACTIVE 并点击 Update status。
状态含义：DRAFT 待核对；ACTIVE 正常服务；PAUSED 暂停服务；COMPLETED 正常结项；CANCELLED 取消。

步骤 8：风险、下一步和家长摘要

Updates → Add update
图 7：高风险记录缺少负责人、下一步或截止时间时，系统不会保存。
风险使用口径行动要求
LOW正常跟进，无明显升级风险。按常规节奏记录。
MEDIUM需要持续观察或专项改善。建议明确下一步和负责人。
HIGH可能明显影响学习、安全、学校关系或服务结果。必须负责人 + 下一步 + 截止时间。
CRITICAL涉及即时安全、严重健康、失联或重大校务危机。先按紧急机制处理，再立即补录完整证据。
自动待办：跟进记录同时填写“下一步 + 截止时间 + 负责人”后，系统会自动创建关联待办，无需重复再建一遍。
家长摘要要求：选择 Parent summary 时必须写公开摘要。内部猜测、敏感原文、其他学生信息和未经确认的责任判断只能写在内部备注。

步骤 10：建立和更新待办

Tasks → Add task
图 9：每个待办必须有负责人、优先级和截止时间；状态变化要及时更新。
状态什么时候用额外要求
OPEN已创建，尚未开始。必须有负责人和截止时间。
IN_PROGRESS已经开始执行。说明里保留当前进展。
WAITING_EXTERNAL等待学校、家长、医疗机构、寄宿家庭等回复。必须设置下次跟进时间。
BLOCKED存在明确阻塞，暂时无法推进。在说明或跟进记录里写明阻塞原因和升级对象。
DONE工作已完成且结果已核验。必须填写完成结果。
CANCELLED事项不再需要执行。保留取消原因的证据记录。
禁止“假完成”：发送了一封邮件不一定代表任务完成。如果目标是“确认学校会议时间”，只有学校回复并确认时间后才能 DONE。

步骤 11：完成待办并填写交付凭证

Task status → DONE
完成操作：
  1. 确认任务目标真的达成。
  2. 状态选择 DONE。
  3. 在“完成时填写结果”写清核验依据。

合格完成凭证：“已核对学校平台，本周作业全部按时提交；写作老师反馈结构较上周改善。”

特殊情况处理

情况立即怎么做系统怎么记录
学生安全、失联、严重健康事件先按紧急机制联系负责人和必要机构，不等待系统录入。事后建立 CRITICAL 风险记录，写清时间线、联系人、行动、结果和下一步。
学校尚未回复不要把任务标为完成。状态改为 WAITING_EXTERNAL，并设置下次跟进时间。
任务被其他问题阻塞确认阻塞原因和需要谁决策。改为 BLOCKED，在跟进记录写明升级对象和解决期限。
家长需要知道，但内部材料敏感整理事实和处理结论，不转发内部原文。内部原文写 Internal note；对外内容写 Parent summary。
服务临时暂停先确认暂停原因、期间责任和恢复条件。ACTIVE → PAUSED；恢复时 PAUSED → ACTIVE。
学生或服务项目选错停止继续录入，通知 Admin / Manager。错误项目改为 CANCELLED，为正确学生重新建立 DRAFT。
CRITICAL 原则：系统记录不能替代报警、医疗、学校或紧急联系人处置。先保安全，再补完整记录。
